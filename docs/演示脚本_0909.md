## 二、演示流程（0~8 步）

### 0. 开场定位（30 秒）
> 话术：我的项目是「AI 辅助接口文档自动生成系统」，它是一个**通用工具**——解析任意 Java/SpringBoot 项目源码，自动提取接口信息，生成 Markdown 和 OpenAPI 双格式文档，还能接入大模型智能增强描述。接口文档靠手写效率低、易漏易过期，这个系统解决的就是这个问题。今天用 Spring 官方示例项目 petclinic 做演示。

### 1. 登录与角色（1 分钟）
- 操作：先展示登录页 → 输入 admin/admin123 登录 → 登录后展示侧边导航
- 话术：v2.2 重构为多页面 SPA——登录/工作台/项目历史/导出中心/用户管理 5 个独立页面，Vue Router 懒加载 + 双重守卫：未登录跳登录页，普通用户进不了管理员页。v2.1 引入了 JWT 鉴权体系，分管理员和普通用户两级。右上角能看到我的角色徽标。

### 2. 用户管理（1 分钟，仅 admin 可见）
- 操作：点左侧「用户管理」菜单进入独立页面 → 展示用户列表、搜索、角色列、删除按钮（admin 自己的删除按钮是禁用的）
- 话术：管理员可以管理全部用户、调整角色；普通用户侧边栏根本看不到这个入口，强行输入 URL 也会被路由守卫拦回工作台。

### 3. 解析项目（2 分钟）
- 操作：上传 `spring-petclinic.zip` → 等待解析 → 展示左侧接口树
- 话术：解析用的是 AST 语法树 + 正则双引擎——javalang 语法树保证准确性，正则兜底保证覆盖率。能识别 Controller、接口方法、参数、注释、返回类型。
- 结果预期：**6 个控制器、17 个接口**（若数字不同以现场为准）

### 4. AI 增强（2 分钟，核心卖点）
- 操作：点开一个接口详情 → 点「AI 增强」→ 展示生成的描述
- 话术（有 Key）：这里接入了 DeepSeek 大模型，用结构化 Prompt 让它补全接口功能描述和参数说明，异步 httpx 调用、信号量控制并发。
- 话术（无 Key / 降级）：系统设计了降级容错——没有配置 Key 时自动降级为规则模板生成，保证核心功能永远可用，这是工程上的可用性设计。
- 若老师追问细节：Prompt 要求 JSON 结构化输出 + 异常捕获 + 超时控制。

### 5. 导出中心（1.5 分钟）
- 操作：点「前往导出中心」→ 展示文档预览页（Markdown/OpenAPI 双 Tab 切换）→ 分别点「下载 Markdown」「下载 OpenAPI JSON」
- 话术：v2.2 新增独立导出中心页，下载前可直接预览文档全貌，OpenAPI 文件可以直接导入 Swagger 或 Apifox 复用。文件名是「项目名_文档类型」，这里还修过一个浏览器下载兼容性 bug（RFC 5987 编码）。

### 6. 项目历史（30 秒）
- 操作：左侧菜单进「项目历史」→ 搜索框输入关键字过滤 → 展示归属人列
- 话术：所有解析过的项目持久化在 MySQL 8.0 数据库，重启不丢；支持按项目名/归属人搜索，从这里可直接进入导出中心或删除项目。历史数据无归属人的标记兼容展示。

### 7. 权限隔离（2 分钟）
- 操作：退出登录 → 用 tester01 登录 → 展示侧边栏菜单变化（无用户管理）→ 展示项目历史列表差异 → （可选）直接访问 admin 项目的 URL 展示 403，访问 #/users 被拦回工作台
- 话术：三层隔离——菜单层（入口隐藏）、路由层（守卫拦截）、数据层（项目归属 403）。历史数据兼容：v2.1 之前解析的旧项目无归属人，对所有登录用户可见。

### 8. 收尾总结（1 分钟）
> 话术：最后总结一下——前端 5 个页面、后端 15 个 API、**78 条 pytest 测试全部通过**（含 24 条鉴权测试），技术栈是 FastAPI + Vue3 + Vue Router + **MySQL 8.0** + JWT，均为当前主流版本。下一步计划是接入真实大模型 Key、补充部署方案。

## 三、高频问题速答（被问到时）

| 问题 | 要点 |
|---|---|
| 为什么做这个系统？ | 手写接口文档效率低、易漏、代码改了文档没改；AI 时代让工具自动生成+增强 |
| 和 Swagger 注解方案比？ | Swagger 需要在代码里写大量注解、侵入业务代码；本系统零侵入，直接读源码 |
| AI 部分怎么实现的？ | httpx 异步调用 DeepSeek API、Prompt 要求 JSON 结构化输出、信号量限并发、无 Key 自动降级 |
| 测试怎么做的？ | pytest 单元+集成 78 条（解析/生成/增强/存储/鉴权五大模块），前端用 Playwright 端到端实测过登录、越权、下载、五个页面路由 |
| JWT 怎么做的？ | 登录签发 token（含 userId/角色），前端 Axios 拦截器统一携带，后端依赖注入校验，401 自动踢回登录页 |
| 前端架构？ | Vue Router 多页面 SPA：5 个页面懒加载分包，MainLayout 侧边导航布局，全局前置守卫做登录+角色双重拦截 |
