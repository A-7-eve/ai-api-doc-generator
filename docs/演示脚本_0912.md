## 二、演示流程（0~9 步）

### 0. 开场定位（30 秒）
> 话术：我的项目是「AI 辅助接口文档自动生成系统」，它是一个**通用工具**——解析 Java/SpringBoot、Python（FastAPI/Flask）、C 三种语言的项目源码，自动提取接口信息，生成 Markdown 和 OpenAPI 双格式文档，还能接入 DeepSeek 大模型智能增强描述。今天用三个语言的示例项目演示。

### 1. 登录与角色（1 分钟）
- 操作：展示登录页 → 输入 admin/admin123 登录 → 展示侧边导航
- 话术：v2.2 重构为多页面 SPA——登录/工作台/项目历史/导出中心/用户管理 5 个独立页面，Vue Router 懒加载 + 双重守卫。v2.1 引入 JWT 鉴权体系，分管理员和普通用户两级。

### 2. 用户管理（1 分钟，仅 admin 可见）
- 操作：点「用户管理」→ 展示用户列表、角色列、删除按钮（admin 自己的删除禁用）
- 话术：管理员管理全部用户与角色；普通用户侧边栏没有入口，强输 URL 会被路由守卫拦回。

### 3. 解析 Java 项目（2 分钟）
- 操作：上传 `spring-petclinic.zip` → 等待解析 → 展示接口树（6 控制器 17 接口，含语言标签 Java）
- 话术：v2.4 升级为**引擎注册表 + 分发器**架构——按扩展名自动识别语言、分发给对应引擎。Java 用 javalang AST 解析 + 正则兜底，保证准确率与覆盖率。
- 结果预期：**6 个控制器、17 个接口**（若数字不同以现场为准）

### 4. AI 增强（2 分钟，核心卖点）
- 操作：点开一个接口详情 → 点「AI 增强」→ 展示生成的描述/参数说明/示例/边界场景/错误码
- 话术：已接入 DeepSeek（deepseek-chat），用**语言自适应 Prompt** 让模型按 Java/Python/C 各自语境补全描述；httpx 异步调用、信号量限并发、异常捕获。没配 Key 时自动降级为规则模板，核心链路永远可用。
- 若追问细节：结构化 JSON 输出 + `_parse_llm_response` 容错（正则提取 JSON 片段）。

### 5. 在线编辑文档（2 分钟，v2.4 核心新增）
- 操作：进入导出中心 → Markdown Tab 直接修改文字 → 点「保存」→ 刷新/重开仍显示编辑版 → 点「重置」恢复生成版
- 话术：v2.4 新增文档在线编辑——生成版与编辑版分离存储（docs 表），编辑后导出与在线一致，可一键重置回退，不会污染生成器。OpenAPI Tab 同样可编辑。
- 若演示时间紧：本步可与第 4 步合并演示（编辑 1 次 + 导出即可）。

### 6. 多语言解析（2 分钟，v2.4 亮点）
- 操作：工作台解析内置示例 flask-demo → 展示 11 个接口（FastAPI+Flask 混合），语言标签 Python；再解析 c-demo → 展示 6 个函数（函数清单）
- 话术：Python 引擎用内置 ast 解析装饰器路由（@app.get/@router.post），无类型注解时从路径占位符推断参数；C 引擎定位为**函数清单**——C 没有 HTTP 路由注解，硬造 HTTP 语义是欺骗，所以生成伪 HTTP 条目（POST/函数名），Markdown 导出正常，OpenAPI paths 为空属预期设计。
- 结果预期：flask-demo **11 接口**、c-demo **6 函数**（static 内部函数不统计）

### 7. 项目历史与持久化（30 秒）
- 操作：进「项目历史」→ 搜索关键字过滤 → 展示归属人列
- 话术：全部解析项目持久化在 MySQL 8.0（项目/接口/文档/用户），重启不丢；历史无归属人的数据兼容展示。

### 8. 权限隔离（1 分钟）
- 操作：退出 → tester01 登录 → 侧边栏无用户管理 → 项目历史只见自己的 → 直接访问 admin 项目 URL 展示 403
- 话术：三层隔离——菜单层（入口隐藏）、路由层（守卫拦截）、数据层（归属 403）。

### 9. 收尾总结（1 分钟）
> 话术：总结——前端 5 个页面、后端 **18 个 API**（业务 12 + 认证 6）、**119 条 pytest 测试全部通过**（含 24 条鉴权 + 41 条多语言/分发/存储），三语言解析引擎 + 在线编辑 + DeepSeek 增强。技术栈 FastAPI + Vue3 + Vue Router + **MySQL 8.0** + JWT，均为当前主流版本。

## 三、高频问题速答（被问到时）

| 问题 | 要点 |
|---|---|
| 为什么做这个系统？ | 手写接口文档效率低、易漏、代码改了文档没改；AI 时代让工具自动生成+增强 |
| 和 Swagger 注解方案比？ | Swagger 需写大量注解、侵入业务代码；本系统零侵入，直接读源码 |
| 多语言怎么实现？ | 引擎注册表 + 分发器：按扩展名识别语言、选择引擎，AST 失败降级正则；languages/engineInfo 字段透明标注 |
| C 语言为什么是函数清单？ | C 无 HTTP 路由注解，硬造 HTTP 语义不诚实；定位为函数清单（Markdown 正常，OpenAPI paths 空属预期） |
| AI 增强怎么实现？ | httpx 异步调 DeepSeek、Prompt 语言自适应、信号量限并发、无 Key 自动降级 |
| 在线编辑怎么实现？ | docs 表存编辑版（project_id+format 联合主键），生成版与编辑版分离，导出优先用编辑版，重置即删记录回退 |
| 测试怎么做的？ | pytest 单元+集成 119 条（三语言解析/生成/增强/存储/鉴权），前端 vite build + Playwright 端到端实测（登录、越权、下载、在线编辑、多语言解析） |
| JWT 怎么做？ | 登录签发 token（含 userId/角色），Axios 拦截器统一携带，后端依赖注入校验，401 自动踢回登录页 |
| Key 安全？ | Key 存 backend/.env（.gitignore 排除），config.py 内置 15 行 .env 加载器，git 历史无泄露 |
