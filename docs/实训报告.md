## 1. 项目概述

### 1.1 项目背景

在软件开发中，接口文档是前后端协作的核心纽带。传统接口文档维护存在以下痛点：

- **手写文档耗时**：开发者需手动编写每个接口的描述、参数说明、示例数据
- **文档与代码不同步**：代码变更后文档忘记更新，导致文档过时
- **Swagger 等注解方案语义不足**：能提取 URL、参数类型，但缺少自然语言描述、示例数据、边界场景说明
- **新人理解成本高**：干瘪的参数列表无法帮助新成员快速理解接口用途

### 1.2 项目目标

构建一个 AI 辅助的接口文档自动生成系统，能够：

1. **自动解析**多语言项目代码——Java/SpringBoot、Python（FastAPI/Flask）、C，自动识别语言并分发对应引擎（v2.4 从仅 Java 扩展）
2. **AI 增强**：接入 DeepSeek 大模型，为每个接口自动生成描述、参数说明、请求/响应示例、边界场景；无 Key 自动降级纯解析
3. **多格式输出**：生成 OpenAPI 3.0 JSON 和 Markdown 格式文档
4. **在线编辑**：生成后可直接在线修改 Markdown/OpenAPI 文档，保存后导出与在线一致，支持一键重置（v2.4 新增）
5. **Web 界面**：登录鉴权、接口浏览、历史项目管理、文档导出

### 3.3 代码解析层实现（v2.4 多语言引擎）

**多语言架构：引擎注册表 + 分发器**

- `engine_registry.py`：每个引擎声明 name/version/languages/syntax_versions/parse_func/fallback，集中注册
- `dispatcher.py` 的 `parse_project_any()`：遍历目录按扩展名分组（.java/.py/.c/.h），逐引擎解析后合并 ProjectMeta，并在 `languages` 字段标注语言清单、`engineInfo` 记录各引擎与降级状态
- 新语言接入只需实现解析函数并注册，上层路由/生成层无感扩展

**三引擎分工：**

| 引擎 | 语言 | 实现方式 | 提取内容 |
|------|------|---------|---------|
| java_parser | Java/SpringBoot | javalang AST + 正则兑底 | @RestController/@Controller、@RequestMapping、参数注解、返回类型、Javadoc |
| python_parser | Python | 内置 ast + 正则兑底 (v2.4) | @app.get/@router.post 等装饰器路由、FastAPI/Flask 参数注解、类型提示 |
| c_parser | C | 正则 (v2.4) | ANSI C 函数签名清单（static 跳过、注释/字符串防误匹配、const 指针类型） |

**Java 解析流程（v2.0 起）：**

1. 遍历项目目录找到 `.java` 文件，`javalang.parse.parse()` 解析为 AST
2. 检查类注解含 `@RestController` / `@Controller`
3. 提取类级 `@RequestMapping` → baseUrl、方法级 `@GetMapping`/`@PostMapping` 等 → HTTP 方法+路径
4. 提取参数与 `@RequestParam`/`@PathVariable`/`@RequestBody` 注解、返回类型、Javadoc、源码片段
5. DTO/Entity 类提取字段名、类型、校验注解；AST 异常自动降级正则

**Python 解析（v2.4）：**

1. `ast.parse()` 解析每个 `.py` 文件
2. 识别模块级与类级路由注册：`@app.get(...)`、`@router.post(...)`、`@app.route(..., methods=[...])` 等
3. 从函数签名提取参数：FastAPI 类型注解参数、Flask 路径参数 `<int:id>`；无注解时降级从路径占位符推断
4. AST 失败（语法过新/过旧）自动降级正则模式并记入 engineInfo

**C 解析（v2.4，函数清单定位）：**

C 语言没有 HTTP 路由注解体系，硬造 HTTP 语义是欺骗。定位为"API 函数清单"：正则匹配 `ret_type func_name(args) {` 函数定义，提取函数名/参数列表/返回类型/上方注释，生成伪 HTTP 条目（method 统一 POST，路径=函数名）。static 内部函数跳过，字符串与注释中的函数样式文本不误匹配。

**关键代码片段（分发器）：**

```python
def parse_project_any(project_path):
    file_groups = _group_by_extension(project_path)  # .java/.py/.c/.h
    for lang, files in file_groups.items():
        engine = engine_registry.select_engine(lang)
        partial = engine.parse(files)  # AST失败自动降级正则
        merged.merge(partial)
    return project_meta  # languages + engineInfo 字段标注
```

### 3.4 AI 增强层实现

**增强策略：** 逐接口增强 + 批量并发

```python
async def enhance_all(endpoints):
    tasks = [enhance_one(ep) for ep in endpoints]
    await asyncio.gather(*tasks, return_exceptions=True)
```

**降级策略（v2.4 双层降级）：**

| 场景 | 降级方案 |
|------|---------|
| 解析层：AST 失败 | 自动降级正则模式，engineInfo 记录 degraded 标记 (v2.4) |
| AI 层：API Key 未配置 | 跳过 AI 增强，使用纯解析结果 |
| API 超时/网络异常 | 保留纯解析结果，description 用方法名推演 |
| 返回非 JSON | 正则提取 JSON 片段；若失败，仅保留文本 |

**Prompt 语言自适应（v2.4）：** 多语言后 prompts.py 按端点语言（Java/Python/C）动态拼接 lang_hint，让大模型知道这是 SpringBoot 控制器、FastAPI/Flask 路由还是 C 函数，描述更贴合实际。

**Markdown 生成：** 使用模板字符串拼接，每个接口包含路径、描述、参数表、示例、边界场景、错误码。

### 3.8 文档在线编辑（v2.4）

**动机：** 生成文档下载后修改再回传繁琐，导出中心直接在线编辑，所见即所得。

**实现要点：**

- 存储层新增 `docs` 表：`(project_id, format, content, updated_at)`，联合主键 `(project_id, format)`；DocStore 提供 get/set/reset/delete_by_project
- 生成版与编辑版分离：`GET doc` 优先返回编辑版（有记录），无编辑版现场生成——不改动生成器，编辑版可随时重置回退
- `export` 导出与在线一致：有编辑版用编辑版，无则现场生成
- 前端 ExportView 预览区改为可编辑 textarea，保存/重置按钮 + 未保存更改离开提示（beforeunload）
- 项目删除联动清理 docs 表，不留孤儿数据

### 3.9 MySQL 持久化（v2.3 从 SQLite 升级）

系统使用 MySQL 8.0 持久化存储（演进路径：内存 dict → SQLite → MySQL），服务重启后数据不丢失。选择 MySQL 的原因：老师对技术栈新颖度有要求（MySQL 8.0+），且生产环境更常用。

**表结构（v2.4，apidoc 库，utf8mb4）：**

```sql
CREATE TABLE projects (
    project_id   VARCHAR(64) PRIMARY KEY,
    project_data MEDIUMTEXT NOT NULL,
    created_at   DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE endpoints (
    endpoint_id   VARCHAR(64) PRIMARY KEY,
    project_id    VARCHAR(64) NOT NULL,
    endpoint_data MEDIUMTEXT NOT NULL,
    updated_at    DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- v2.4 新增：文档在线编辑（生成版与编辑版分离）
CREATE TABLE docs (
    project_id   VARCHAR(64) NOT NULL,
    format       VARCHAR(16) NOT NULL,   -- markdown / openapi
    content      MEDIUMTEXT NOT NULL,
    updated_at   DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (project_id, format)
);

-- v2.1 新增：用户表
CREATE TABLE users (
    user_id       CHAR(36) PRIMARY KEY,
    username      VARCHAR(64) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    role          VARCHAR(16) NOT NULL DEFAULT 'user',
    created_at    VARCHAR(64) NOT NULL
);
```

`ProjectStore`、`EndpointStore`、`DocStore`（v2.4）类提供与原 dict 兼容的接口（`__getitem__`、`__setitem__`、`get`、`__contains__`），上层路由代码无需改动即可使用 MySQL 持久化。`UserStore` 提供 users 表的增删改查。

**Key 安全管理（v2.4）：** DeepSeek API Key 不写入任何被 git 跟踪的代码文件，存放于 `backend/.env`（已被 .gitignore 排除）。后端 `config.py` 内置约 15 行 `_load_dotenv()` 加载器（环境变量优先），无需引入额外依赖。已用 `git check-ignore` 验证 .env 不会进仓库，git 历史无 Key 泄露。

**迁移要点（v2.3）：** 服务启动自动建库建表（`CREATE DATABASE IF NOT EXISTS apidoc`，utf8mb4）；连接配置在 `config.py`，支持 `APIDOC_DB_HOST` 等环境变量覆盖；历史 SQLite 数据（12 项目/204 接口/2 用户）已通过迁移脚本完整迁入并逐表校验一致，原 `backend/data/apidoc.db` 保留作备份；单元测试使用独立测试库 `apidoc_test` 隔离，不污染真实数据。

### 3.10 用户角色与鉴权实现（v2.1）

**实现要点：**

| 模块 | 文件 | 说明 |
|------|------|------|
| 密码哈希 | store.py | pbkdf2_hmac(sha256, 10万轮) + 16字节随机盐 |

## 6. 遇到的问题与解决方案

### 6.1 javalang ElementArrayValue 属性名问题

**问题：** `javalang` 库的 `ElementArrayValue` 对象没有 `value` 属性，而是 `values`（列表类型）。导致解析 `@GetMapping({"/vets.json", "/vets.xml"})` 时报 `AttributeError`。

**解决：** 将 `ann.element.value.value` 改为遍历 `ann.element.values` 列表，取第一个元素。

### 6.2 FastAPI 路由前缀重复

**问题：** `APIRouter` 定义了 `prefix="/api"`，`main.py` 中 `include_router` 又传了 `prefix="/api"`，导致实际路径变成 `/api/api/parse-sample`，返回 404。

**解决：** 去掉 `main.py` 中 `include_router` 的 `prefix` 参数，保留 `APIRouter` 自身的前缀。

### 6.3 parse-sample 调用 parse 函数的参数冲突

**问题：** `parse_sample` 通过 `await parse(path=...)` 调用 `parse` 函数，但 `parse` 的 `file` 参数是 `File(default=None)` 类型，直接 Python 调用时 `file` 可能不为 `None`，触发"file 和 path 只能二选一"校验。

**解决：** 将 `parse_sample` 改为内联逻辑，不调用 `parse` 函数，直接执行解析→增强流程。

### 6.4 petclinic 使用 @Controller 而非 @RestController

**问题：** spring-petclinic 使用 `@Controller` 注解而非 `@RestController`，且没有类级 `@RequestMapping`，接口路径直接写在方法注解上。

**解决：** 解析器兼容 `@Controller` 注解；无类级 `@RequestMapping` 时 `baseUrl` 设为空字符串，直接使用方法级完整路径。已补充到设计文档容错策略中。

### 6.5 无 API Key 时的 AI 增强降级

**问题：** 没有 DeepSeek API Key 时，AI 增强无法执行。

**解决：** 实现降级策略——`enhancer.py` 检测到 `LLM_API_KEY` 为空时，跳过 API 调用，使用方法名生成降级描述（如 `GET /owners/{ownerId} - showOwner（AI增强不可用，纯解析结果）`），系统仍能正常运行。v2.4 已接入真实 DeepSeek Key，此降级作为容错保留。

### 6.6 正则兜底接入

**问题：** 初版代码中 `regex_fallback.py` 已编写但从未被 `java_parser.py` 导入，javalang 解析失败时直接跳过文件，设计文档中描述的"AST + 正则双重解析"实际不存在。

**解决：** 在 `java_parser.py` 中导入 `regex_parse_file`，javalang 解析异常时自动降级为正则解析，提取 Controller、接口、参数等基本信息。同时重写了 `regex_fallback.py`，使其返回与 AST 解析相同的 `ControllerMeta`/`EndpointMeta` 结构。

### 6.7 内存存储改为持久化存储（v2.1 SQLite → v2.3 MySQL）

**问题：** 原系统使用内存 dict 存储数据，服务重启后所有项目数据丢失，不满足毕业设计要求。

**解决：** 先引入 SQLite 持久化（v2.1），`store.py` 中 `ProjectStore`/`EndpointStore` 封装数据库操作，对外提供与 dict 兼容的接口，上层路由代码改动最小化。v2.3 按技术栈新颖度要求将存储层升级为 MySQL 8.0（pymysql 驱动），启动自动建库建表，历史数据迁移脚本逐表校验一致，单元测试用独立测试库隔离；原 SQLite 文件保留作备份。v2.4 在存储层追加 docs 表支撑文档在线编辑。

### 6.8 前端单文件拆分为多组件

**问题：** 初版前端 `App.vue` 达 630 行，包含工具栏、接口树、详情面板等全部逻辑，可读性和可维护性差。

**解决：** 拆分为 3 个子组件（`AppHeader.vue`/`ApiTree.vue`/`EndpointDetail.vue`）+ 1 个主容器（`App.vue`），通过 `defineProps`/`defineEmits` 进行父子组件通信，每个组件职责单一。

### 6.9 导出文件名变成 UUID 且无扩展名（v2.1 修复）

**问题：** 前端导出文档时，下载的文件名是 UUID 乱码且无扩展名，无法直接打开。

**排查：** 抓包确认后端响应头 Content-Disposition 已正确下发文件名；问题出在前端——`<a>` 标签未挂载到 DOM 就触发 click，部分浏览器会忽略 download 属性。

**解决：** 双端修复：后端按 RFC 5987 下发 `filename*` 编码头（兼容中文文件名）；前端解析响应头取文件名，`appendChild` 挂载 DOM 后再点击。实测下载文件名正确。

### 6.10 退出登录后项目数据残留（v2.1 修复）

**问题：** 用户 A 退出后，用户 B 登录，左侧仍显示 A 解析的项目树（数据泄露观感）。

**解决：** 退出登录时同时清空 project/activeEndpoint 状态。后端 API 层面本就有归属隔离，此为纯前端展示层问题。

### 6.11 JWT 密钥长度安全警告

**问题：** pytest 运行时 PyJWT 报 InsecureKeyLengthWarning，HMAC 密钥低于 RFC 7518 建议的 32 字节。

**解决：** 默认密钥加长至 40 字节，并支持环境变量 JWT_SECRET_KEY 覆盖，警告消除。

### 6.12 Python 解析器的类型注解默认值问题（v2.4）

**问题：** `_extract_params` 读取 FastAPI 参数默认值时，`arg.default` 在无默认值场景下解析异常，导致部分 Python 接口参数提取报错。

**解决：** 对 `arg.default` 取值增加存在性判断与容错，无默认值时回退为必填标记；已由 test_python_parser 覆盖验证。

### 6.13 pytest 临时目录权限冲突（v2.4）

**问题：** Windows 上 pytest 默认临时目录 `pytest-of-柒柒`（C 盘用户目录）被拒绝访问（WinError 5），测试无法启动。

**解决：** 运行 pytest 时显式指定 `--basetemp=.temp\pytest-tmpN` 使用项目内临时目录，避开系统用户目录权限问题。

### 6.14 多语言分发的路径前缀误判（v2.4）

**问题：** `detect_languages` 原实现判断路径前缀含 "." 就跳过整棵树，导致项目放在 .temp 等隐藏目录下时全部被误跳过。

**解决：** 改为只判断目录名本身是否以 "." 开头，项目根目录（无论是否含点）正常解析。

### 6.15 pydantic 模型不可动态属性（v2.4）

**问题：** `EndpointMeta` 是 pydantic 模型，不可动态挂属性、不可 hash，无法直接在端点对象上标记语言。

**解决：** 用 `id(endpoint)` 作 key 在 `_LANG_TAGS` 字典中存储端点语言标记，enhancer 通过对象 id 查询语言，规避模型限制。
